Add a Metal platform.

A native Metal platform for Apple GPUs. Like CUDA and HIP, it's a thin ComputeContext on the common compute framework, and every common kernel compiles unchanged. Plain C++ with vendored metal-cpp: no Objective-C, and no Xcode.

Built using Claude Fable 5.1, with a rigorous scientific and testing approach, under my direction.
0.99–1.07×Metal single over OpenCL on OpenMM's benchmark suite. 1.20–1.28× on FAHBench dhfr
11×Metal mixed over CPU. Apple's OpenCL has no mixed precision
1.21e-6force error on dhfr, identical to OpenCL on every chip
6,507lines in platforms/metal src and include. HIP 7,604, CUDA 7,828

DesignCommand buffers and precision.

Command buffers. Kernels encode into one open command buffer, which is committed only when the host needs a result. TestMetalCommandBatching measures 1.01 command buffers per step without a cutoff, and 2.01 with PME.

Precision. Single precision is native. Apple GPUs have no fp64, so mixed precision uses float-float (df64) arithmetic, stored as IEEE doubles in device memory. Host code and array layouts are the same as on the other platforms. Applying a transcendental to a mixed value is a compile error naming the function and the line, never a silent fallback to float. Double precision isn't offered.

PerformanceOpenMM's benchmark suite.

OpenMM's benchmark.py, unmodified, on all nine non-AMOEBA tests. Metal single runs at 0.99 to 1.07 times OpenCL. These systems constrain only bonds to hydrogen, so none uses CCMA; FAHBench's dhfr, the one system where Metal leads clearly, sends 3,072 constraints to CCMA. Whether CCMA is the cause is not yet isolated. Mixed precision costs 15 to 42% against Metal single. Clock: benchmark.py's host wall clock, one 60 s run per configuration.

AccuracyAgainst Reference in double.

Force error matches OpenCL on all three chips: 1.21e-6 on dhfr, and 1.75e-6 on nav (OpenCL 1.80e-6 to 1.82e-6). Energy error is at most 2.2e-6. df64 is within 7e-15 of a host double closed form.

ScopeChanges outside platforms/metal.

CMakeLists.txtOPENMM_BUILD_METAL_LIB, on by default for arm64 macOS.
ComputeContext.hdoubleToString is now virtual, for df64 constants. ABI change: plugins must be rebuilt.
Common kernelsA PRIVATE address-space macro, empty on CUDA, OpenCL and HIP, plus (mixed) 0 literals. Other platforms generate the same code.
minimize.ccWithout 64-bit atomics, the nine atomicAddMixed kernels run as a single threadgroup. Launches are unchanged elsewhere.
vkFFT.hFixes to VkFFT's Metal backend, all inside VKFFT_BACKEND==5.
DocsLicenses (metal-cpp is Apache 2.0) and a user guide section.

LimitationsStated plainly.

  • Mixed-precision minimization reduces within a single threadgroup: nav takes 264 s, against 58 s in single precision and 300 s on CPU.
  • QTBIntegrator is single precision only.
  • One device per context, so the multi-device tests are skipped.
  • Requires macOS 15 or later and an Apple7 or newer GPU (M1 or later).
  • Not yet tested on M1 or M4 hardware, or on the AMOEBA benchmarks: Metal has no AMOEBA plugin.

OpenMM on MetalLab report 017
Scientific computing · September 23, 2026

Step one: bringing scientific compute to Apple silicon.

OpenMM, the molecular dynamics engine behind Folding@home's GPU work, now runs natively on Apple GPUs through Metal. On an M2, an M3 Pro and an M3 Ultra, it runs every Folding@home benchmark work unit in the precision Folding@home's science requires, with the accuracy of established GPU platforms.

An independent open-source effort. Built with Claude (Fable 5.1 and Opus 5.5) using a rigorous scientific and testing approach, under human supervision and direction. Not yet reviewed or accepted by the OpenMM or Folding@home teams.

WhyRemarkable GPUs, sitting out of science.

Every Mac with Apple silicon carries a capable GPU, unified memory and outstanding performance per watt. Yet when a Mac joins Folding@home today, it can contribute through its CPU alone.

The reason is a chain of dependencies. Folding@home's GPU cores are built on OpenMM. OpenMM speaks CUDA, HIP and OpenCL, but not Metal. Apple's OpenCL has been deprecated since 2018, and it can't run the mixed precision Folding@home depends on, because Apple GPUs have no 64-bit floating-point hardware.

So the first link in the chain has to be OpenMM itself.

Every Mac with Apple silicon has a capable GPU. Not one of them can contribute GPU work to Folding@home yet.

What we builtA native Metal platform, built the way OpenMM's own platforms are.

The platform follows the design of OpenMM's CUDA and HIP platforms: a thin layer on OpenMM's common compute framework. Every one of OpenMM's shared GPU kernels compiles for Metal unchanged. It's written in plain C++ against Apple's metal-cpp headers, with no Objective-C, and it builds without Xcode.

The hard part was precision. Mixed precision keeps positions and velocities in 64-bit doubles. On Apple GPUs, the platform represents each double as a pair of 32-bit floats, a technique known as double-float. Over one integration step, it agrees with true double precision to within 7 parts in 1015.

Just as important is what it refuses to do. If a calculation would quietly fall back to single precision, the platform stops with an error that names the function and the line, rather than returning a subtly wrong answer.

PerformanceFaster than OpenCL. Up to eleven times faster than the CPU.

We ran Folding@home's three benchmark work units on all three chips. They range from a 2,489-atom protein in implicit solvent to a 173,000-atom system in explicit water. Each configuration ran three times, in rotated order, on the same build.

In single precision, Metal leads OpenCL everywhere. The margin is small on the implicit-solvent and largest systems, and 20 to 28 percent on dhfr, a 23,558-atom system with PME electrostatics. In mixed precision, the only mode OpenCL can't offer at all, Metal runs 2.8 to 11 times faster than the CPU in the same machine.

ScalingThe bigger the system, the more the big chips shine.

To see how each GPU fills up, we ran water boxes from 2,700 to 792,000 atoms. Throughput climbs until the GPU is saturated, then holds. The M2 and M3 Pro deliver the same work per GPU core. The M3 Ultra, two dies joined by UltraFusion, reaches 11.7 million atom·ns/day, and Apple's OpenCL tops out at the same ceiling.

AccuracySpeed means nothing without the right answer.

Every result was checked against OpenMM's Reference platform, which computes in full double precision on the CPU. On all three chips, Metal's forces match OpenCL's to three significant figures. Energy conservation shows no signal beyond the spread the CPU itself shows from machine to machine.

TestsOpenMM's own test suite, on every chip.

We ported OpenMM's OpenCL test suite to Metal: 110 tests, each program in single and mixed precision. The only repeatable failure is testLargeForces, and that one fails the same way on unmodified OpenMM with Apple's OpenCL on M3 GPUs. It's an existing upstream issue, which we're reporting separately.

What comes nextThis is step one.

No Mac folds for Folding@home yet. The project accepts results only from its own signed GPU cores, so three more steps have to happen, and none of them is ours alone to take.

    Folding@home
  4. Apple GPU detectionThe Folding@home client must recognize GPUs that aren't on PCI (fah-client-bastet #303).
    Folding@home

Some gaps remain. Energy minimization in mixed precision is correct but slow, because Apple GPUs lack 64-bit atomics. There's no double-float version of the trigonometric functions. And the platform has yet to run on M1 or M4 hardware, or through OpenMM's standard benchmark suite.

MethodHow we measured.

BuildA git archive of commit f9347f6c5, built on each machine with matching source hashes. Apple clang 21.0.0, Release.
MachinesMac mini, M2, 10 GPU cores, 8 GB. MacBook Pro, M3 Pro, 18 GPU cores, 36 GB. Mac Studio, M3 Ultra, 60 GPU cores, 96 GB. All on macOS 27.0.
TimingHost wall clock (time.perf_counter) over whole steps, at nice 0, with configuration order rotated every round.
ConditionsThe M3 Pro ran its first round on battery and the rest on AC. The M3 Ultra ran alongside a dictation app and two virtual machines, so its CPU timings vary by up to 16%.

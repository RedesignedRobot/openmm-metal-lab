@epretti yes, it differs by GPU family. On the M2, `(long)` of an out-of-range float saturates to ±2^63; on the M3 Ultra it wraps mod 2^64. Only signed 64-bit wraps: `int`, `uint` and `ulong` saturate on both, and ±inf and NaN give 0 on M3. The M3 Pro fails on the same macOS build as the passing M2 (27.0 26A428), so it's the chip, not the OS. The test's forces are ≥ 2.2e22, and x·2^32 in float is an exact multiple of 2^64, so every component lands on exactly 0.

`convert_long_sat` saturates correctly on M3. With it in `realToFixedPoint`, the test passes 3/3 on the M3 Ultra. customCppForce, pythonForce, atmforce, customCentroidBond and the minimizer's constraint forces cast directly and would need to go through it too. Happy to open a PR if that approach suits you.

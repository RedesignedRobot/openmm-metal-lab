Title: testLargeForces fails on OpenCL (single) on Apple M3 GPUs, passes on M2

TestOpenCLLocalEnergyMinimizer fails in single precision on Apple M3 GPUs, on unmodified main
(3c9effc96):

  $ ./TestOpenCLLocalEnergyMinimizer single
  exception: Assertion failure at TestLocalEnergyMinimizer.h:229

Line 229 is `ASSERT(maxdist > 1.0)` in testLargeForces: after minimizing ten nearly overlapping
particles with tolerance 1.0, none of them ended up more than 1 nm from the origin. The test uses
a fixed seed, and the result is the same on every run.

All machines run macOS 27.0 (26A428) with Apple clang 21.0.0.

  Machine                               OpenCL single    Reference, CPU
  Mac mini, M2 (10 GPU cores)           pass (3/3)       pass
  MacBook Pro, M3 Pro (18 GPU cores)    fail (4/4)       pass
  Mac Studio, M3 Ultra (60 GPU cores)   fail (3/3)       pass

A Metal platform in progress (#5397) shows the same split: it fails this test on the M3 Pro and
the M3 Ultra, and passes it on the M2.

OpenCL mixed and double can't run on any of these ("No compatible OpenCL platform is available").

Repro:

  git checkout 3c9effc96
  cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DOPENMM_BUILD_OPENCL_LIB=ON \
      -DOPENMM_BUILD_OPENCL_TESTS=ON -DOPENMM_BUILD_PYTHON_WRAPPERS=OFF \
      -DOPENMM_BUILD_C_AND_FORTRAN_WRAPPERS=OFF
  ninja -C build TestOpenCLLocalEnergyMinimizer
  build/TestOpenCLLocalEnergyMinimizer single

The test dates from 2018. The likely area is the GPU L-BFGS (#5198), which moved minimization onto
the GPU and changed how large forces are handled in single precision.

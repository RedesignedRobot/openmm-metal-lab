# Saturate float to fixed point conversions in OpenCL

Fixes #5434.

Converting an out-of-range float to `long` is undefined in OpenCL C. On Apple M3 GPUs it wraps modulo 2^64. On the M2 it saturates, as it does on NVIDIA. The minimizer detects overflowing forces by looking for fixed point values near ±2^63. On M3, the forces in `testLargeForces` became exactly 0, the gradient norm was 0, and L-BFGS stopped at its starting point.

- `realToFixedPoint` in common.cl uses `convert_long_sat`.
- Five common kernels converted with a plain cast and now go through `realToFixedPoint`: customCppForce, pythonForce, atmforce, customCentroidBond and `getConstraintEnergyForces` in minimize.cc. atmforce and customCentroidBond already hold fixed point values, so they divide by 2^32 first. That is exact.
- CUDA and HIP keep their own `realToFixedPoint`, unchanged.

One behavior change: `getConstraintEnergyForces` now passes `kdr*delta` through `realToFixedPoint(real)`. In mixed precision on CUDA and OpenCL, it is rounded to float before the conversion, as every other force already is. HIP has a double overload, so it is unchanged there. If you'd rather keep it in mixed, I can add a `mixed` overload instead.

Tested on an M3 Ultra, macOS 27.2: the OpenCL tests pass 66 of 66 with this change, and 65 of 66 on master. The one failure on master is `TestOpenCLLocalEnergyMinimizerSingle`. Apple's OpenCL has no double precision, so those tests weren't built. I haven't tested on CUDA or HIP hardware.

This agrees with @philipturner's expectation: on apoa1rf the neighbour search is a third of GPU time on the older chip, so the ceiling from making it free is about 1.5x there and 1.34x on apoa1pme. One caveat: the absolute times Apple's OpenCL layer reports look like mach ticks and not nanoseconds (the sum is about 0.15 ms per step against 4.9 ms of wall time), so I only trust the fractions.

**Is MSL close enough to share the Common kernels?** I tried it. A macro prelude plus one mechanical signature rewrite, kernel files byte-identical to master, compiled at runtime with `newLibraryWithSource` on macOS 27:

- 49 of the 67 files in `platforms/common/src/kernels` compile with zero errors. That is every file that holds complete kernels.
- The other 18 are the code fragments that the host splices into generated kernels (bondForce.cc, coulombLennardJones.cc, customNonbonded.cc and so on). They cannot compile alone on any platform. I have not yet tested them spliced the way the host does it.
- What made it work:
  - Current MSL accepts thread position builtins declared at program scope (`uint3 gid [[thread_position_in_grid]];`). `GLOBAL_ID`, `LOCAL_ID`, `GROUP_ID` and the size macros stay parameterless and work from helper functions. I ran this on the M2 and the M3 Ultra and the values are right.
  - Buffer indices are assigned automatically to pointer arguments. Value arguments need rewriting to `constant T&` with a local copy at function entry; that is the one mechanical rewrite.
  - `thread` is a keyword in MSL and a variable name in some kernels, handled with a define.
  - `simd_ballot`, `simd_shuffle`, `simd_shuffle_down` and `simd_shuffle_xor` exist, so the `BALLOT` and `SHFL` paths that the HIP platform uses map directly. The census compiled the Common kernels with those paths switched on.
- What it does not show: compiling is not running. The prelude's `erf` and `erfc` are polynomial stand-ins that need an accuracy check, MSL has no 64-bit atomics (the prelude's split-word substitute is not safe under contention and needs a real design), and nonbonded.cl, findInteractingBlocks.cl, sort.cl and the FFT live outside Common and need Metal versions of their own.

**Float atomics on older chips.** `atomic<float>` fetch_add builds and gives right sums on the M2, not only on M3 and later. Under worst-case contention (2^20 threads adding into 8 cells) it takes 191 ms on the M2 against 0.34 ms on the M3 Ultra, which looks like a compare-exchange loop against a hardware path. Charge spreading has far lower contention than that probe, so whether float-atomic spreading beats the fixed-point route plus finishSpreadCharge on M1 and M2 is something I can measure next.
